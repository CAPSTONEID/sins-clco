# 옵션 2 영상 스타일 프로파일

옵션 2 영상은 제작 전에 아래 다섯 프로파일 중 하나를 사용자가 고른다. 선택한 프로파일은 롱폼과 숏폼에 함께 적용하며, 한 영상 안에서 프로파일을 섞지 않는다. 사용자가 이미 스타일 이름을 말했더라도 컬러 계획은 별도 질문으로 다시 확정한다.

## 공통 잠금 규칙

사용자가 명시한 컬러·전사 자막 요구는 이 문서의 기본값보다 우선한다. 확정된 컬러는 다시 묻지 않으며, 요청받은 숏폼 전사 자막은 음성 타이밍에 맞춰 안전영역에 표시한다. 아래 자막 금지 검수는 자막을 요청하지 않은 제작에 적용한다.

- 사람 얼굴, 발표자 캠, 토킹헤드, 프로필 사진, 얼굴이 보이는 스톡 이미지를 넣지 않는다. 원본 영상에 사람이 있더라도 얼굴 영역은 사용하지 않고 화면·손·제품·문서·도형으로 대체한다.
- 전사 결과는 내용 파악과 타이밍 계산에만 사용한다. 롱폼·숏폼 모두 음성을 그대로 받아쓴 자막, `.sf-caption`, SRT/VTT, 자막 문안 TXT를 만들지 않는다.
- 화면 텍스트는 자막이 아니라 장면을 설명하는 제목·키워드·라벨·카드 문구다. 발화를 문장 단위로 복제하지 않고 핵심만 2~5어절로 압축한다.
- 렌더 규격, 안전영역, 좌우 확대 여백, 편 번호 노출 금지, CTA 문구·길이, 실제 재생 검수는 기존 옵션 2 규칙을 유지한다.
- **롱폼 고정 요소(다섯 프로파일 공통, 롱폼만):** 시작 0.2~5.2초 좌측 하단(left 120·top 992)에 `자막이 필요하신 분은 유튜브 자막 기능을 이용해 주세요.`를 박스 없이 띄우고, 본편이 끝난 뒤 정확히 21.0초 동안 텍스트 없는 움직이는 그라디언트 화면을 붙인다. 이 안내 문구는 창·종이·타일 바깥에 있어도 금지된 외부 제목·상태 배지가 아니다. 세부 규격은 SKILL.md "롱폼 고정 요소"를 따른다. 숏폼에는 넣지 않는다.
- 모든 프로파일에서 컬러 계획을 질문으로 확정한 뒤 제작한다. `60/30/10`을 각각 배경·주요 글자/표면·포인트에 연결하고 대비 4.5:1 이상을 확보한다.
- **다섯 프로파일 모두 마우스 포인터를 인터랙션 모티프로 사용한다.** 각 본문 장면에서 카드 선택·붙이기·강조·전환 중 최소 한 번 `.video-cursor`가 등장해 대상과 상호작용한다. 읽는 홀드 구간에는 숨길 수 있지만 해당 스타일에서 포인터 자체를 생략하지 않는다.
- 공통 포인터는 별도 이미지 파일을 쓰지 않는 **표준 시스템 화살표**로 통일한다. `.video-cursor.cursor-standard[data-cursor-style="system"]`를 CSS 또는 인라인 SVG로 만들고 흰 채움·검정 외곽선·짧은 그림자를 사용한다. 롱폼 `56×56px`, 숏폼 `64×64px`를 기준으로 하며 포인터 전체가 화면 안전영역 안에 들도록 한다. 과거 사용자 지정 포인터 이미지와 그 파생 PNG는 사용하지 않는다. `scripts/verify-video-cursor.js`를 포인터 경로의 시작·클릭·종료 프레임에서 실행한다.
- 포인터를 제외한 일반 아이콘은 `https://koboyo.com/icons?q={keyword}`의 검색 결과에서만 가져온다. 기업·브랜드 로고는 `https://logos.lndev.me/`에서만 가져오며, 없으면 브랜드명을 텍스트로 쓴다. 아이콘·로고의 검색어와 원본 URL을 자산 원장에 남긴다.

### 클릭·선택 강조: 글자색만 변경

- 옵션 2의 모든 프로파일에서 클릭·선택의 기본 반응은 **핵심 라벨/키워드의 `color`만 승인된 선택색(`--accent`)으로 0.20~0.35초에 걸쳐 변경**하는 것이다. 카드 전체나 부모의 `color`를 변경해 아이콘·보조 설명까지 물들이지 않는다. `.selection-label`처럼 대상 글자를 명시한다.
- 클릭·호버로 선택 박스, 선택 바, 채움 배경, 테두리, `outline`, `box-shadow`, 배경 스윕을 새로 만들거나 기존 값/불투명도를 바꾸지 않는다. `::before`·`::after`나 숨겨진 오버레이로 같은 효과를 우회하지 않는다. 선택 시 크기·굵기·밑줄도 추가하지 않는다.
- 기존 창·카드의 정적 구조선, 표면색, 그림자는 그대로 유지한다. 등장·폴더 열기·창 전환·정보 펼침 모션과 선택 반응을 분리하며, 네오 브루탈리즘의 본래 외곽선·하드 섀도를 제거하지 않는다. 커서 이동과 포인터 위치의 짧은 클릭 리플은 유지하되 리플이 카드 외곽이나 라벨을 감싸는 선택 박스가 되어서는 안 된다.
- 보조 설명은 원래 본문색을 유지한다. 폰트 로딩 뒤 실제 배경과 강조 전/후 글자색의 대비를 측정한다(일반 글자 4.5:1, 큰 글자 3:1 이상). 승인색이 작은 라벨에서 기준에 미달하면 큰 키워드로 강조 대상을 옮기고 작은 설명은 본문색으로 유지한다. 승인 팔레트를 임의로 바꾸지 않는다.
- 각 본문 장면의 클릭 직전·색 전환 중간·전환 완료/홀드 프레임을 검수한다. 대상 라벨의 계산된 `color`가 바뀌는지, 카드/행과 의사 요소의 `background`, `border`, `outline`, `box-shadow` 값 및 선택 오버레이의 표시/불투명도가 변하지 않는지 확인한다. hover 경유 패턴도 같은 기준으로 검사한다. 최종 MP4에서 각 프로파일·화면비의 대표 장면과 수정한 문제 장면을 추출해 글자 가독성·보조 설명 보존·선택 박스 부재를 확인한다. CSS 검색이나 인코딩 성공만으로 검수를 대체하지 않는다.

## 1. 페이퍼 콜라주 (`paper-collage`)

기존 `paper-briefing` 스타일을 그대로 유지한다. 세부 규칙은 [paper-briefing.md](paper-briefing.md)를 읽는다.

- 풀프레임 미색 종이, 섬유 결, 찢은 종이, 사진 컷아웃, 마스킹테이프, 잉크 밑줄을 사용한다.
- 카드·번호·비교 패널은 **공통 `.video-cursor`**가 종이 조각을 붙이거나 선택·펼치기·분류·교정하는 방식으로 상호작용한다. [장면·모션 변주](paper-motion-variety.md)를 함께 적용한다. 손 모양이나 사람 실사는 사용하지 않는다.
- `tear-wipe`, `paper-push`, `collage-snap`을 사용하고 중앙 갈라짐 전환은 금지한다.
- 기존 `scripts/verify-paper-frame.js`와 실제 렌더 확인을 사용한다.

## 2. 맥 파인더창 (`finder-motion`)

사용자 제공 레퍼런스는 [Grok Bot 실사용 꿀팁 10가지](https://www.youtube.com/watch?v=Mvy4jCpwNKQ&t=405s)다. 링크의 화면을 복제하지 않고, 사용자가 지정한 **맥 파인더창 시각 문법**과 레퍼런스의 빠른 설명 리듬만 적용한다.

### 화면 문법

- 캔버스를 데스크톱 작업 공간처럼 구성하고, 콘텐츠를 Finder형 파일 브라우저 창·폴더·파일 카드·정보 패널 안에 배치한다.
- 화면 바깥의 `STYLE 02`, `MAC FINDER WINDOW` 같은 스타일 설명용 제목은 만들지 않는다. Finder 창 자체가 화면의 주인공이어야 한다.
- 현재 영상 세션 제목을 Finder의 열린 폴더명으로 사용한다. `.fm-session-title`을 타이틀바와 경로 표시줄에 동일하게 노출하고, `data-session-title` 값과 정확히 일치시킨다. `Motion Library` 같은 고정 폴더명은 쓰지 않는다.
- 창은 상단 타이틀바, 좌측 트래픽 라이트 3개, 얇은 툴바, 사이드바, 경로 표시, 목록/아이콘 보기 중 장면에 필요한 부분만 사용한다.
- 한 장면의 주창은 활성 창 하나가 맡는다. 보조 창은 최대 2개이며, 모두 같은 깊이에 정렬하지 말고 앞뒤 크기와 겹침을 달리한다.
- 실제 Apple 로고, 실제 사용자 이름, 실제 파일 경로, 얼굴이 있는 프로필 이미지는 넣지 않는다. 일반 폴더·문서·도표 아이콘과 익명 라벨을 쓴다.
- 과도한 유리 블러보다 선명한 창 표면과 핵심 글자색 강조를 우선한다. 컬러 계획에 맞춰 라이트 또는 다크 Finder 톤을 만들 수 있다.
- 창 밖 배경은 컬러 계획의 60색을 사용한 **평평한 단색 면**으로 둔다. 사선·원근·청사진·격자선 등 장식용 배경 그리드는 사용하지 않는다.
- 창 바깥 우상단에 `READY`, `DONE`, 진행 상태 같은 독립 배지나 상태 텍스트를 두지 않는다. 상태는 필요한 경우 Finder 창 내부의 선택·진행 UI로만 표현한다.

### 레이아웃 잠금 규칙

파인더 스타일은 창 모양보다 **정렬된 정보 구조**가 먼저다. 아래 좌표 관계를 컴포넌트 계약으로 고정하며, 장면마다 눈대중으로 위치를 바꾸지 않는다.

- 1920×1080 기준 외곽 안전영역은 `x 120~1800`, `y 60~1020`이다. Finder 창과 포인터의 외곽선·그림자를 이 안에 둔다.
- `.fm-heading` 같은 외부 화면 제목은 금지한다. 세션 제목은 반드시 창 내부 `.fm-session-title` 폴더명으로만 표현한다.
- 주창 `.fm-window`는 화면 폭의 **82% 이상**, 높이의 **80% 이상**을 차지하며 권장 크기는 `1680×900`이다. 화면 중앙에 놓고 안전영역을 넘지 않는다.
- 창 내부는 `타이틀바 64px / 선택 툴바 52px / 본문`의 수평 밴드로 나눈다. 밴드 경계는 창 전체 폭을 정확히 가로지르며 중간에서 끊기지 않는다.
- 사이드바는 창 본문의 **고정 22%** 또는 롱폼 320px 중 작은 값으로 유지한다. 사이드바와 콘텐츠 사이 경계선을 장면마다 움직이지 않는다.
- 콘텐츠 영역은 안쪽 여백 32px, 열 간격 24px의 그리드를 쓴다. 같은 행의 파일 카드는 폭·높이·상단선·라벨 기준선이 같아야 한다. 카드가 3개면 `repeat(3, 1fr)`, 4개면 `repeat(4, 1fr)`로 균등 분할한다.
- 파일 아이콘은 각 카드의 수평 중앙, 파일명은 아이콘 아래 동일한 기준선에 둔다. 클릭 시 파일명 또는 핵심 라벨의 글자색만 선택색으로 바꾸며 카드 테두리·배경·아이콘색은 바꾸지 않는다.
- `.fm-quicklook`은 콘텐츠 그리드의 오른쪽 또는 아래쪽에 **별도 셀**로 배치한다. 파일 카드 위에 임의로 걸치거나 창 밖으로 튀어나오지 않는다. 카드 행과 최소 24px 간격을 둔다.
- 겹치는 보조 창은 주창과 같은 내부 그리드를 사용한다. 장식용으로 비뚤어진 창·서로 다른 카드 폭·불규칙한 패딩을 만들지 않는다.
- 요소 계층은 `배경 < 보조 창 < 주창(글자색 강조 포함) < 포인터` 순서로 고정한다. 포인터 외에는 콘텐츠가 타이틀 영역을 침범할 수 없다.

### 타이틀 비겹침 계약

- 타이틀바의 폴더명(`.fm-session-title`)과 장면 본문 타이틀(`.sf-title`, `.lf-title`)을 구분한다. 본문 타이틀을 스테이지 절대 좌표로 창 전체 위에 얹지 않는다.
- 기본 구조는 툴바 아래 `.fm-content` 안에 `제목 → 설명(있을 때) → 시각 본문`을 서로 다른 Grid/Flex 행으로 배치한다. 제목의 왼쪽은 사이드바 오른쪽 경계 + 콘텐츠 패딩 이후, 오른쪽은 창 안쪽 패딩 이전이어야 한다. 사이드바 세로 구분선이 제목 글자를 관통하면 실패다.
- 숏폼에서 제목 폭이 부족하면 툴바 아래에 창 내부 전폭 제목 전용 행을 만들 수 있다. 이 경우 사이드바와 시각 본문은 모두 제목 행 아래에서 시작해야 하며, 사이드바 배경·세로 경계선도 제목 행까지 올라오면 안 된다. 창 바깥에 제목을 추가하지 않는다.
- 제목은 툴바 아래와 시각 본문 위에 각각 최소 24px 여백을 확보한다(각 영상의 설계 좌표 기준). 긴 제목은 의미 단위로 최대 2줄 배치하고, 공간 부족 시 문구를 줄이거나 본문 높이·시작 위치를 조정한다. `z-index` 상향, 가림용 배경, `overflow:hidden`으로 겹침을 숨기는 방식은 수정으로 인정하지 않는다.
- 폰트 로딩 뒤 제목의 실제 텍스트 영역과 사이드바·툴바·문서·카드의 영역을 같은 좌표계에서 측정한다. 가시 제목 영역과 이 요소들의 교차 면적은 0이어야 하며, 제목은 자신의 전용 행 안에 완전히 들어가야 한다. 등장·강조·홀드·퇴장 구간의 이동과 스케일 최대값도 확인한다.
- 롱폼과 숏폼을 각각 검수한다. 특히 숏폼 첫 장면 및 가장 긴 두 줄 제목 장면을 최종 렌더에서 확대 확인한다. 겹침 허용 속성(`data-layout-allow-overlap` 등)이 있어도 이 타이틀 검수를 생략하지 않는다.

### 연결선·문서 정렬 검수

- `flow`·`timeline`의 연결선과 노드는 같은 좌표계를 사용한다. 세로 중앙 정렬된 노드에 고정 `top` 값의 선을 따로 두지 않는다. 가로 선은 아이콘 중심 Y, 세로 선은 번호 원 중심 X에 맞추고 시작·끝은 첫/마지막 노드 중심에 둔다. 선이 노드 바깥으로 돌출하지 않아야 한다.
- 아이콘·번호는 `flex-shrink:0`을 적용하고 번호의 높이와 `line-height`를 명시한다. 라벨 길이나 폰트 로딩으로 연결 기준점이 바뀌지 않게 한다. 연결선은 노드 뒤에 두고 노드 배경은 선을 가릴 만큼 불투명하게 한다.
- `document`·`split-document`의 기본 문서 구조는 제목 → 설명 → 본문 폭의 단일 구분선 → 세로 번호 목록이다. 짧은 강조선과 열별 `border-top`을 겹쳐 끊어진 선처럼 보이게 만들지 않는다. 표가 필요한 장면은 의도적인 표 구조로 별도 설계한다.
- 문서 행의 텍스트 flex 자식에는 `min-width:0;flex:1`을 적용한다. 제목·보조 설명·메타데이터가 시트 또는 인접 행과 겹치지 않는지 확인한다.
- 연결선 위치를 CSS 수치만으로 통과시키지 않는다. 폰트 로딩과 등장 종료 뒤 노드 중심과 선 중심의 오차가 설계 좌표 기준 2px 이내인지 측정한다. 클릭·드래그 중에는 선과 노드의 관계가 유지되는지 확인하고, 필요하면 노드 전체 대신 내부 아이콘에 반응 모션을 적용한다.
- 수정한 장면의 등장 완료·강조·홀드 프레임을 확인한 뒤 최종 MP4에서도 같은 시점을 추출해 확대 검수한다. 롱폼 가로 연결선과 숏폼 세로 연결선을 각각 확인한다. 린트·인코딩 성공만으로 시각 검수를 대체하지 않는다.

### 마우스 포인터 잠금 규칙

- `.fm-cursor`는 `.cursor-standard[data-cursor-style="system"]`인 일반 시스템 화살표만 사용한다. 외부 포인터 이미지, 사용자 지정 SVG, 과장된 브러시형 꼬리는 사용하지 않는다.
- 표시 크기는 롱폼 `56×56px`, 숏폼 `64×64px`로 통일한다. 정사각형 종횡비를 유지하고 컨테이너에 `overflow:hidden`을 걸지 않는다.
- 포인터의 **전체 bounding box**를 화면 안전영역에서 최소 24px, 창 외곽에서 최소 16px 떨어뜨린다. 좌표를 핫스폿만 기준으로 검사하지 않는다.
- 클릭 대상 위에서는 화살촉만 대상 안으로 들어가고 몸통은 라벨을 가리지 않게 둔다. 파일명·수치·타이틀과 겹치면 대상을 옮기지 말고 포인터 경로를 수정한다.
- 포인터가 화면 또는 창 경계에 가까워지는 동작은 최종 좌표를 `clamp()`해서 멈춘다. 모션 블러·스케일 오버슈트까지 포함한 최대 외곽선이 안전영역을 넘으면 실패다.

### 필수 모션

이 프로파일은 정적 Finder 목업이 아니다. **카드, 텍스트, 장면 전환에 모두 움직임이 있어야 한다.**

- 창 등장: 0.45~0.75초 동안 `scale .82→1`, `y 70→0`, `opacity 0→1`을 조합하고 마지막 3~5% 오버슈트로 안착한다.
- 파일·카드 등장: 파일이 폴더에서 펼쳐지거나 그리드 셀에 0.06~0.10초 간격으로 스태거된다. 등장 완료 후 클릭 반응은 핵심 라벨의 글자색 변경만 사용한다. 정적 카드 그림자와 배경은 유지한다.
- 텍스트 등장: 파일명 타이핑, 글자 마스크 리빌, 마스크 슬라이드, 행 단위 와이프 중 하나를 사용한다. 단순 페이드만 쓰지 않는다.
- 강조: 커서가 항목을 선택하면 핵심 라벨/키워드의 `color`만 0.20~0.35초 동안 승인 선택색으로 바뀐다. 상세 패널 열기는 정보 전개가 필요할 때 별도 모션으로 쓰며, 선택 바·선택 배경·선택 테두리·그림자 압착은 쓰지 않는다.
- 전환: 폴더 더블클릭 줌인, 창 최대화, 창 스택 재배열, 선택 파일 퀵룩 확대, 드래그 앤 드롭 중 장면 의미에 맞는 동작을 쓴다.
- 한 장면에서 큰 동작은 2개까지 겹치고, 보조 요소는 0.04~0.08초 스태거로 이어 붙인다. 읽을 핵심이 안착한 뒤 0.8초 이상 유지한다.
- 같은 창 최대화 전환을 3회 연속 사용하지 않는다. 한 편에 전환 어휘 4종 이상을 사용한다.

### 검수

- `scripts/verify-finder-frame.js`를 등장 종료·강조 중간·장면 종료 프레임에서 실행해 외부 제목 부재, 창 점유율, 세션 제목 폴더명, 창 내부 밴드, 사이드바, 카드 균등 그리드, 퀵룩 셀, 포인터 전체 경계가 모두 통과하는지 확인한다.
- 창이 화면 밖으로 잘리지 않고 안전영역 안에서 제목·파일명·선택 상태가 읽히는지 확인한다. 같은 행의 카드 크기와 기준선이 2px 이상 다르면 다시 정렬한다.
- 포인터는 표준 화살표의 화살촉·몸통·검정 외곽선이 시작·클릭·종료 프레임에서 완전히 보이는지 확대 확인한다.
- 창 바깥 배경에 장식용 그리드가 없고, 우상단을 포함한 창 바깥에 `READY`류 상태 배지가 없는지 확인한다.
- 모든 본문 장면에서 `창/카드 등장 + 텍스트 등장`이 각각 최소 한 번 있는지 확인한다.
- 장면 전환이 단순 크로스페이드로 끝난 곳이 없는지 실제 렌더를 재생해 확인한다.
- 얼굴·발표자 캠·프로필 사진·전사 자막이 한 프레임도 없는지 확인한다.

## 3. 네오 브루탈리즘 (`neo-brutalism`)

### 화면 문법

- 고채도 단색 또는 따뜻한 미색 배경, 검정 4~8px 외곽선, 10~18px 하드 섀도, 낮은 라운드 또는 직각 모서리를 사용한다.
- 카드·라벨·버튼형 블록·큰 숫자·굵은 구분선으로 정보를 구조화한다. 유리 블러, 은은한 소프트 섀도, 금속 광택, 사실적 3D는 쓰지 않는다.
- 제목은 크게, 보조 문구는 짧게 쓴다. 카드 안에 대본 문단을 넣지 않고 키워드·수치·한 줄 설명으로 나눈다.
- 색은 배경 1색, 표면/글자 1색, 포인트 1색을 중심으로 하고 검정 외곽선을 구조색으로 사용한다. 포인트색을 모든 카드에 동일 면적으로 칠하지 않는다.
- 배경은 단색 면으로 유지한다. 반복 사선·바둑판·원근선·격자 패턴을 깔지 않으며 시선은 카드와 타이포 움직임에 집중시킨다.

### 필수 모션

이 프로파일은 포스터 한 장을 흔드는 방식이 아니다. **카드, 텍스트, 장면 전환을 각자 움직인다.**

- 카드 등장: `x/y 80~160px` 진입, `rotate ±3~7°`, 하드 섀도 18→10px 압착, `scale .9→1.04→1`의 짧은 펀치 인을 사용한다.
- 텍스트 등장: 글자 또는 단어 블록이 0.03~0.06초 간격으로 스태거되며, 블랙 바 리빌·수직 슬라이스·스탬프 인 중 하나로 나타난다.
- 강조: 선택 시 핵심 라벨/키워드의 `color`만 0.20~0.35초 동안 승인 선택색으로 바꾼다. 본래 외곽선·하드 섀도와 표면색은 유지한다.
- 포인터: 공통 표준 `.video-cursor.cursor-standard`가 카드 모서리나 버튼형 블록을 클릭하면 핵심 글자색이 바뀌며 포인터 위치에 짧은 클릭 리플이 나타난다. 클릭으로 카드 테두리·배경·하드 섀도를 변경하지 않는다. 흰 채움·검정 외곽선의 일반 시스템 화살표 형태를 유지한다.
- 전환: 컬러 블록 와이프, 카드 충돌 밀어내기, 컬러 셀 교체, 대형 타이포가 화면을 가로질러 다음 장면을 여는 전환을 사용한다.
- 기본 전환은 0.28~0.55초, 카드/텍스트 조립은 0.35~0.8초다. 화려함은 속도·충돌·스태거에서 만들고 지속적인 화면 흔들림은 쓰지 않는다.
- 한 장면에 강조 모션 2종까지, 한 편에 전환 어휘 4종 이상을 사용한다. 같은 방향의 슬라이드 인을 3회 연속 쓰지 않는다.

### 검수

- 모든 본문 장면에서 `카드/도형 등장 + 텍스트 등장`이 각각 최소 한 번 있는지 확인한다.
- 각 본문 장면에 공통 포인터 상호작용이 최소 한 번 있는지, `scripts/verify-video-cursor.js`가 시작·클릭·종료 프레임에서 통과하는지 확인한다.
- 외곽선과 하드 섀도가 축소 화면에서도 구분되는지, 그림자가 글자를 침범하지 않는지 확인한다.
- 전환 중 텍스트가 반으로 잘린 채 오래 머물거나 안전영역 밖으로 튀지 않는지 확인한다.
- 얼굴·발표자 캠·프로필 사진·전사 자막이 한 프레임도 없는지 확인한다.

## 4. 다이내믹 타일 창 (`tile-motion`)

사용자 제공 레퍼런스는 [OpenAI Dev Day 풀 리뷰](https://www.youtube.com/watch?v=7PtGto3vAeI)의 0~34초 구간이다. 링크의 화면·사이트·발표자를 복제하지 않고, **창 크기가 끊임없이 바뀌는 타일링 리듬**만 가져온다. 레퍼런스에 보이는 우하단 발표자 캠, 하단 전사 자막, 실제 도메인 URL, 화면 밖으로 잘린 창은 모두 이 스킬의 금지 항목이므로 쓰지 않는다. 캠 자리를 비우지 않고 타일로 채운다.

### 화면 문법

- 화면 전체는 컬러 계획 60색의 **평평한 단색 면**이다. 그 위에 브라우저형 창(`.tw-pane`)이 1~4개 타일 격자로 깔린다. 창과 창 사이 간격은 **16px**로 고정하고, 창들이 합쳐져 타일 필드(`.tw-field`)의 85% 이상을 항상 덮는다. 빈 필드·어긋난 간격·겹친 창은 실패다.
- 각 창은 상단 **타이틀바(`.tw-bar`, 롱폼 36px / 숏폼 44px)** 와 본문으로 나뉜다. 타이틀바 왼쪽에 8px 점 3개(본문색 30%), 가운데 경로 라벨(`.tw-path`, 본문 폰트 18px, 자간 .04em), 오른쪽에 출처 태그(`.tw-tag`, 2~5자, 1px 외곽 알약)와 선택적 카운터(`.tw-counter`, `000`→`NNN` 3자리)를 둔다.
- 경로 라벨은 `세션 슬러그 / 장면 키워드` 형식의 **가짜 경로**다. 실제 도메인, 실제 파일 경로, 실제 사용자 이름을 쓰지 않는다. 브랜드 로고는 logos.lndev.me 규칙을 따르고 없으면 텍스트로 쓴다.
- 출처 태그는 `공식 자료`, `직접 실행`, `실측`, `인용`처럼 그 창의 **정보 성격**만 적는다. 편 번호·`READY`·`DONE` 같은 상태 배지로 쓰지 않는다. 창 바깥에는 어떤 제목·배지·상태 텍스트도 두지 않는다.
- 창 표면은 60색에 30색을 4~8% 섞은 면, 외곽은 1px `color-mix(in srgb, var(--text) 14%, transparent)`, 라운드 10px이다. 그림자·유리 블러·장식 그리드는 쓰지 않는다. 이 1px 외곽선은 정적 구조선이며 클릭·활성 여부로 바뀌지 않는다.
- 창 안의 본문은 기존 **본문 형태 13종**에서 고른다. 타일 격자 상태(단일·분할·4분할·레일)는 바깥 껍데기이므로 `data-layout-variant`로 세지 않는다. 창 안 큰 수치(`bigstat` 숫자, 게이지 값)는 `.tw-value`로 표시해 검증기가 포인터 겹침·썸네일 유출을 검사하게 한다. 비트맵 소재는 가로 2560px 이상 규칙을 그대로 지키고, 실제 웹 스크린샷으로 창을 채우지 않는다.
- 활성 창은 한 장면에 **정확히 하나**이며 `.tw-pane.is-active`로 표시한다. 활성 표시는 타이틀바 경로 라벨 `.tw-path`의 **글자색만** 선택색으로 바꾸는 것이다. 빨간 외곽선·선택 배경·그림자 변경은 쓰지 않는다. 레퍼런스의 붉은 테두리는 복제하지 않는다.
- 지나간 창은 **레일(`.tw-rail`)** 로 밀려 썸네일(`.tw-thumb`)이 된다. 롱폼은 왼쪽 세로 레일(폭 240px, 썸네일 240×136, 간격 16px, 최대 5개), 숏폼은 위쪽 가로 레일(높이 136px, 썸네일 240×136, 최대 3개)이다. 썸네일은 타이틀바와 축소 본문만 보이고 글자는 읽히지 않아도 된다.
- 다음 창 미리보기(`.tw-peek`)는 **필드 안쪽** 가장자리(롱폼 x 1800 경계, 숏폼 하단 경계)에 폭 48~96px 세로/가로 띠로만 둔다. 화면 밖으로 창을 내보내지 않고, 띠 안에 제목·수치 같은 필수 정보를 넣지 않는다.

### 레이아웃 상태표 (롱폼 1920×1080)

타일 필드는 `x 120~1800, y 90~990`(1680×900)이다. 아래 여섯 상태만 쓰고, 좌표는 전 장면 공통이다. 눈대중으로 창 크기를 정하지 않는다.

| 상태 | 창 배치 | 창 크기 (가로×세로) |
|---|---|---|
| `solo` | 창 1개 | 1680×900 |
| `split` | 좌우 2개 | 832×900 ×2 |
| `quad` | 2×2 | 832×442 ×4 |
| `rail-quad` | 레일 240 + 2×2 | 704×442 ×4 |

- 모든 간격(창↔창, 레일↔창)은 16px이다. 합이 1680/900과 정확히 맞는지 배치 전에 더해 본다.
- 한 편에서 상태 4종 이상을 쓰고, 같은 상태를 3장면 연속 유지하지 않는다. `solo`는 후킹·결론 장면에만 쓴다.
- 제목은 **활성 창 안** `.tw-heading` 행에 둔다. 타이틀바 아래 24px 여백 → 제목(최대 2줄) → 보조 한 줄 → 시각 본문 순서이며, 창 바깥이나 다른 창 위에 제목을 얹지 않는다. 파인더 프로파일의 [타이틀 비겹침 계약](#타이틀-비겹침-계약)을 그대로 적용한다.
- 제목 크기는 `solo`·`split`·큰 창이 기본 76px 또는 SM 60px, `quad`·오른쪽/아래 작은 창은 **44px**(이 프로파일 전용 XS, 2줄 이내)이다. XL 96px은 `solo` 한정, 한 편 최대 2장면이다.
- 작은 창(464×442, 704×324)의 본문은 `bigstat`·`gauge`·`metaphor`·`wordfill`·`contain`처럼 요소 수가 적은 형태를 쓴다. 카드 4개·flow 4노드는 큰 창에서만 쓴다.

### 마우스 포인터 잠금 규칙

- `.tw-cursor`는 공통 `.cursor-standard[data-cursor-style="system"]` 표준 화살표만 쓴다. 롱폼 56×56px, 숏폼 64×64px, 전체 bounding box가 안전영역 안쪽 24px, 창 외곽 16px을 지킨다. 경계 근처 좌표는 `clamp()`로 멈춘다.
- 이 프로파일 전용 포인터 패턴 3종을 공통 패턴표에 더한다. ① **분할선 드래그** — 창 사이 16px 간격(`.tw-divider`)을 잡고 끌어 비율을 바꾼 뒤 상태표 좌표로 스냅한다. ② **레일 썸네일 클릭** — 썸네일을 클릭하면 그 창이 필드로 승격된다. ③ **타이틀바 끌기** — 창을 다른 셀로 끌어 놓으면 두 창이 자리를 바꾼다. 기존 직접 클릭·2단 경유·호버 후 선택도 창 안 본문에 그대로 쓴다.
- 포인터 클릭의 반응은 공통 규칙대로 핵심 라벨 글자색 변경과 포인터 위치 리플뿐이다. 창 크기 변경은 전환 모션이지 클릭 강조가 아니다.

### 필수 모션

이 프로파일의 주인공은 **창 크기가 바뀌는 순간**이다. 새 창이 들어오는 동안 기존 창이 동시에 줄어들어야 하며, 창 하나만 움직이고 나머지가 멈춰 있으면 실패다.

- 전환 어휘 6종: `tile-split`(새 창이 오른쪽/아래 가장자리에서 들어오며 기존 창이 동시에 축소), `tile-promote`(작은 창과 큰 창의 자리 교환), `tile-demote`(창이 축소되며 레일 썸네일 자리로 이동, 레일의 기존 썸네일은 0.05초 스태거로 밀림), `tile-maximize`(활성 창이 필드 전체로 커지고 나머지가 레일로 흡수), `tile-rail-push`(레일에 새 썸네일이 들어오며 마지막 썸네일이 밀려 페이드 아웃), `tile-peek`(미리보기 띠가 `tile-split`으로 확장). 한 편에 4종 이상을 쓰고 같은 전환을 3회 연속 쓰지 않는다. 크로스페이드만으로 장면을 바꾸지 않는다.
- 리사이즈 규격: 한 전환에서 움직이는 모든 창은 **같은 길이(0.55~0.7초)·같은 이징(`power3.inOut`)** 으로 `x/y/width/height`를 동시에 바꾼다. 시작 시차는 0.08초 이하다. 창을 `scale`로 늘려 글자를 왜곡하지 않고, 창 크기에 맞춰 내부 콘텐츠를 다시 흐르게 한다. 마지막 2~3% 오버슈트로 안착한다.
- 전환 중 z-순서: 전환 시작 시각에 **커지는 창을 위(`z-index` 3), 작아지는·레일로 가는 창을 아래(1)** 로 둔다. 창들이 서로를 가로지를 때 축소 중인 창이 승격 중인 창을 가리면 안 된다. 전환이 끝나면 모두 같은 층으로 되돌린다.
- 필드 밖에서 대기하는 창·레일·미리보기 띠는 `visibility:hidden`(GSAP `autoAlpha`)으로 둔다. `opacity:0`만으로는 `verify-tile-frame.js`·`verify-frame.js`가 그 창을 측정해 `pane-field-bounds`·`zoom-right`가 난다. `fromTo`에는 `immediateRender:false`를 준다.
- 창 등장(필드에 처음 들어오는 창): 가장자리 밖 또는 미리보기 띠에서 `opacity 0→1`과 함께 자리로 확장한다. 등장 뒤 0.8초 이상 모든 창이 멈춘 상태를 유지한다.
- 텍스트 등장: 경로 라벨 타이핑, 제목 마스크 리빌, 행 단위 와이프 중 하나를 쓴다. 단순 페이드만 쓰지 않는다.
- 카운터: `직접 실행`·`실측` 태그가 붙은 창은 `.tw-counter`가 활성 구간 동안 `000`에서 올라간다(0.8초 `power2.out` 또는 장면 길이 선형). 숫자는 정지 상태로 두지 않는다.
- 강조: 활성 창 전환 시 새 활성 창의 `.tw-path` 색만 0.20~0.35초에 선택색으로, 이전 활성 창은 본문색으로 돌아간다. 창 본문의 클릭 강조도 글자색만 바꾼다.
- 한 장면에 큰 전환 1종 + 본문 강조 모션 2종까지 겹친다. 창 흔들림·지속 글로우·배경 모션은 쓰지 않는다.

### 검수

- `scripts/verify-tile-frame.js`를 전환 종료·강조 중간·장면 종료 프레임에서 실행해 필드 안전영역, 창 개수(1~4), 16px 간격, 85% 덮임, 창 비겹침, 타이틀바 높이·정렬, 활성 창 1개와 `.tw-path`·`.tw-heading` 위치, 레일 크기, 미리보기 띠 폭, 외부 제목·배지·장식 그리드 부재, 포인터 크기·안전영역을 모두 통과하는지 확인한다.
- `scripts/verify-frame.js`는 이 프로파일에서 슬롯 검사가 없는 전용 모드 `__verifyFrame('tile-longform')` / `__verifyFrame('tile-shortform')`로 실행한다(`safe-*`·`zoom-*`·`episode-number`·`forbidden-element`만). 제목이 활성 창 안에 들어가므로 `.lf-*`·`.sf-*` 슬롯 좌표(`slot-*`·`missing`·`underfill`)는 `verify-tile-frame.js`의 덮임률·제목 위치 검사가 대신한다. 숏폼 CTA 씬은 그대로 `shortform-cta` 모드다.
- 전환 중간 프레임을 뽑아 움직이는 창이 **모두** 같은 시각에 이동 중인지 확인한다. 한 창만 움직이고 나머지가 정지해 있으면 재작업한다.
- 활성 창의 `.tw-path` 글자색만 바뀌었는지, 창 외곽선·표면·그림자가 전환 전후 같은지 계산된 스타일로 확인한다.
- 레일 썸네일과 미리보기 띠에 제목·수치가 들어 있지 않은지, 어떤 창도 x 1800(숏폼 898)·화면 밖으로 나가지 않는지 확인한다.
- 실제 도메인·실제 경로·실제 사용자 이름이 경로 라벨에 없는지, 출처 태그가 편 번호·상태 배지로 쓰이지 않았는지 확인한다.
- 얼굴·발표자 캠·프로필 사진·전사 자막이 한 프레임도 없는지 확인한다.

## 5. 노드 줌 프로세스 (`node-zoom`)

영상 전체를 **하나의 공정도**로 보여 주는 스타일이다. 노드와 연결선이 놓인 큰 월드(`.nz-world`)를 카메라(`.nz-camera`)가 줌·팬한다. 내레이션이 어떤 항목을 말하면 카메라가 그 노드로 줌인해 화면을 채우고 내용이 펼쳐진다. 다음 항목으로 넘어갈 때는 줌아웃해 두 노드와 연결선을 보여 준 뒤 다음 노드로 줌인한다. 시청자는 지금 전체 흐름의 어디에 있는지를 계속 본다. 기준 엔진과 58초 미리보기는 `~/Library/CloudStorage/Dropbox/📦 My Contents/videos/node-zoom-sample/`(`shared/node-zoom.js`·`node-zoom.css`, `tools/build.py`·`verify.py`)에 있다. 실제 제작은 `tools/build.py`의 `NODES` 데이터만 대본에 맞게 바꾼다.

### 화면 문법

- 화면 바깥은 컬러 계획 60색의 **평평한 단색 면**이다. 장식 그리드·파티클·배경 모션을 쓰지 않는다. 움직임의 주인공은 카메라다.
- **손그림 테마가 기본이다.** 반듯한 디지털 선은 딱딱해 보인다는 사용자 피드백(2026-10-27)에 따라 노드 외곽·연결선·화살표·구분선·미터·링을 손으로 그은 선으로 그린다. 글꼴은 스킬 고정 규칙(제목 국민대해공체 400, 본문 Presentation 300)을 그대로 쓴다.
- **노드(`.nz-node`)** 는 60색에 30색을 5% 섞은 면(라운드 28px)이며 CSS 테두리를 쓰지 않는다. 그 위에 스케치 외곽선(`.nz-sketch`)을 얹는다. 네 변을 각각 한 획으로 긋되, 양 끝을 지나치게 긋고(롱폼 최대 26, 숏폼 20 월드px) 가운데를 살짝 휘게(8/7) 한다. 같은 선을 다른 시드로 한 번 더 덧그린다(투명도 .45). 시드 고정 난수라 재렌더해도 같은 선이 나온다. 선 두께는 배율과 무관하게 화면 2.2px로 유지한다(`--sk = 2.2 / scale`). 오프닝에서 노드가 나타날 때 외곽선이 그려진다. 그림자·글로우는 쓰지 않는다.
- **연결선(`.nz-edge`)** 은 노드 사이 베지어(일렬 배치라 거의 곧은 선)를 **7점**으로 샘플링하고 가운데로 갈수록 살짝(주선 10, 덧선 14 월드px) 흔든 손그림 곡선이며, 끝에 손그림 화살표(`.nz-arrow`, 날개 26°±5°)를 단다. 점을 많이 넣으면 번개처럼 꺾여 지그재그로 보이므로 늘리지 않는다. 기본선은 본문색 42% + 덧선, 지나온 구간은 포인트색 선(`.nz-edge-on`)과 포인트색 화살표가 덮어 그려진다. 선 두께는 화면 2.6px로 고정한다(`--sw = 2.6 / scale`). 롱폼은 노드 오른쪽 가운데 → 다음 노드 왼쪽 가운데, 숏폼은 아래 가운데 → 다음 노드 위 가운데로 잇는다.
- **시맨틱 줌**: 노드 안에 칩(`.nz-chip`)과 상세(`.nz-detail`) 두 층을 둔다. 오버뷰·이동 중에는 칩(큰 번호·라벨·아이콘, 롱폼은 보조 한 줄)만, 초점에서는 상세만 보인다. 칩 글자는 오버뷰 배율에서 읽히도록 월드 단위로 크게 쓰되 노드 가장자리에서 넉넉히 띄운다(롱폼 x 180·번호 170·라벨 240·보조 104, 숏폼 x 96·번호 130·라벨 200).
- **상세 레이아웃 — 여백 우선**(노드 로컬 좌표, 초점 배율 1이라 설계 px와 같다). 노드 안이 꽉 차 보인다는 피드백에 따라 안쪽 패딩을 롱폼 104px·숏폼 64px로 두고 글자를 한 단계 줄였다. 본문 글자는 키워드 26~28px, 보조 20px, 큰 수치 롱폼 120·숏폼 112px이다:

|---|---|---|
| 머리줄 `.nz-step`·`.nz-kicker`·`.nz-tag`(테두리 없는 글자) | y 58, 20px | y 48, 20px |

- **손그림 강조:** 제목 강조어 아래에 손글씨 밑줄(`.nz-scribble`, 포인트색 75%)을 달아 제목 리빌 직후 그린다. 미터·막대·링·타임라인 선·구분선·지도 선에는 SVG 변위 필터(`#nz-rough`, `#nz-rough-ring`)를 걸어 살짝 흔든다. 글자가 든 요소에는 필터를 걸지 않는다(글자가 일그러진다). 문서 시트는 면 위에 연한 스케치 외곽선을 얹는다.
- 본문은 기존 **본문 형태 13종**에서 노드마다 고르고 `data-layout-variant`로 기록한다. 노드 외곽은 형태로 세지 않는다. 같은 형태를 이웃 노드에 연속으로 쓰지 않는다. 숏폼 `gauge`는 링 2개, `compare`·`pictogrid`·`timeline`은 세로 쌓기다.
- **월드 제목**(`.nz-wtitle`, 영상 주제 + 한 줄 부제)은 노드 열 위에 두며 **오버뷰에서만** 보인다. 줌인·이동 중에는 숨긴다. 화면 가장자리에서 잘린 큰 제목이 지나가면 지저분해 보인다.
- **공정 지도(`.nz-map`, 롱폼 전용)**: 초점 상태에서 화면 상단 x 120~1800·y 66~102에 `01 기획 ── 02 대본 ── …`을 고정한다. 현재 단계는 점과 라벨 글자색만 포인트색, 지난 단계는 본문색, 남은 단계는 보조색이다. 숏폼은 자리가 없어 머리줄의 `02 / 06`이 대신한다.
- **숏폼 이웃 노드**: 초점 상태에서 다음 노드의 위쪽 끝이 하단 데드존(y 1620~)에 걸쳐 보인다. 이 빈 상자는 다음 단계를 예고하는 장치다. 대신 초점 동안 다른 노드의 칩은 모두 숨겨 데드존에 글자가 남지 않게 한다.

### 카메라 상태표

| 상태 | 롱폼 | 숏폼 |
|---|---|---|
| 초점 프레임 (배율 1) | 노드 → x 120·y 130·1680×820 | 노드 → x 120·y 300·778×1000 |
| 오버뷰 필드 | x 120~1800·y 90~990, 월드 전체(제목 포함)를 0.94로 맞춤 | x 120~898·y 228~1346 |
| 이동 중간 | 두 노드 중점, 두 노드 + 여유 30%가 들어오는 배율 | 같음 |
| 월드 배치 | 노드 간격 360, **모든 노드 y 0 — 가로 일렬** | 노드 간격 320, **모든 노드 x 0 — 세로 일렬** |

- 노드는 한 줄로 반듯하게 놓는다. 위아래(숏폼은 좌우)로 오가는 지그재그·흩어진 배치는 산만해 보인다는 피드백(2026-10-27)에 따라 쓰지 않는다. 손그림 느낌은 선의 질감으로만 낸다.

- **줌아웃 트윈과 줌인 트윈을 따로 이어 붙이지 않는다.** 가장 멀리 빠진 순간 배율 속도가 최대인 채로 방향이 뒤집혀 튕겨 보인다(실측: 프레임당 ln 배율 변화 급변 0.209 → 연속 곡선 0.005, 팬 가속 83.5 → 4.3px/프레임²). 확대 상태에서 팬이 먼저 시작되면 화면이 미끄러지므로 팬은 줌아웃이 충분히 진행된 뒤 몰아서 한다.
- 카메라는 `{cx, cy, ln(scale), X, Y}` 프록시를 GSAP로 트윈하고 `onUpdate`에서 transform을 쓴다. **배율은 로그로 보간**해야 줌 속도가 일정하게 느껴진다. 엔진은 `force3D` 없이 2D transform만 쓴다(합성 레이어가 작은 배율로 래스터돼 글자가 뭉개지는 것을 막는다).
- 노드 수는 롱폼 4~8개, 숏폼 4~6개다. 더 많으면 오버뷰에서 칩 글자가 20px 아래로 내려가므로 챕터로 나눠 공정도를 두 장으로 만든다.

### 타이밍 (노드 하나 = 초점 체류 + 이동)

| 구간 | 기본값 | 내용 |
|---|---|---|
| 오프닝 오버뷰 | 0 ~ 3.4초 | 월드 제목, 노드 0.28초 간격 팝, 기본 연결선 드로잉, 느린 푸시 |
| 첫 줌인 | 3.0 ~ 5.0초 (`power2.inOut`) | 칩 0.6초 페이드아웃 → 상세 리빌 |
| 초점 체류 `FD` | 5.8초 | 머리줄 → 제목 마스크 리빌 → 부제 → 본문 형태 인트로 → 다음 버튼, 커서 상호작용, 아이콘 아이들 |
| 이동 `TR` | 2.2초 | **하나의 연속 곡선**(`flyTo`). 진행도 p는 `sine.inOut`, ln(배율)은 `lerp − dip·sin(πp)`로 빠졌다 돌아오고, 팬은 p 12~88% 구간에 smoothstep으로 몰린다. 상세·칩 크로스페이드 0.5~0.6초 `power1.inOut`. 지나온 연결선이 포인트색으로 그려지고 이동 절반 시점에 지도의 현재 단계가 넘어간다 |
| 엔딩 오버뷰 | 마지막 노드 뒤 2.2초 줌아웃(`power2.inOut`) + 홀드 | 칩 번호가 0.2초 간격으로 포인트색으로 바뀌며 공정 완료를 보여 준다. 느린 푸시 1.05배 |

- 실제 제작에서는 각 노드의 초점 시작을 **그 항목을 말하기 시작하는 시각 − 0.2초**에 맞추고, 체류 시간은 내레이션 길이를 따른다. 12초를 넘는 항목은 노드를 둘로 나누거나 노드 안에서 본문 형태를 한 번 교체한다.
- 롱폼 고정 요소(시작 자막 안내·21초 아웃트로)와 숏폼 2초 CTA는 공통 규칙대로 붙인다. 아웃트로·CTA는 엔딩 오버뷰 뒤에 이어진다.

### 마우스 포인터

- 공통 `.video-cursor.cursor-standard[data-cursor-style="system"]`(롱폼 56·숏폼 64px)를 화면 레이어에 둔다. 월드 안에 넣지 않는다(카메라와 함께 확대되면 안 된다).
- 노드마다 두 번 상호작용한다. ① 본문 안 항목 라벨 클릭은 노드마다 패턴을 바꾼다: 직접 클릭 / 호버 후 선택 / 더블클릭 / 2단 경유 / 누른 채 짧은 이동. ② **다음 버튼 클릭**은 이 프로파일의 서명 동작이며 매 노드 같다. 클릭 0.6초 뒤(`FD − 0.6`) 카메라 이동이 시작된다.
- 이동 중에는 커서를 숨기고(0.2초), 다음 노드 초점 0.6초 뒤 같은 화면 위치에서 다시 보인다. 경로 끝 좌표는 커서 안전영역으로 clamp한다.
- 클릭 반응은 공통 규칙대로 대상 라벨 글자색만 바뀐다. 노드 외곽선·면·연결선은 클릭으로 바뀌지 않는다.

### 필수 모션

- 줌인·줌아웃·팬 자체가 장면 전환이다. 크로스페이드·컷으로 노드를 바꾸지 않는다.
- 줌 중에 상세를 미리 보이지 않는다. 칩은 줌인의 마지막 40% 동안 사라지고, 상세는 카메라가 안착하기 0.2초 전부터 리빌된다.
- 텍스트 등장: 제목은 `clip-path` 마스크 리빌, 머리줄은 x 슬라이드 스태거, 부제·본문 글자는 y 16 → 0 페이드업. 본문 형태별 강조는 공통 모션 어휘(카운트업·링 스윕·바 그로우·선 드로잉·마스크 와이프·아이콘 팝)에서 짝지어 쓴다.
- 초점 체류 중 아이콘은 ±5° 아이들 회전(유한 반복)을 한다. 3초 이상 정지 화면을 만들지 않는다.

### 검수

- `scripts/verify-node-frame.js`를 초점 노드마다 **리빌 직후·클릭 직후·이동 직전** 세 시점, 오버뷰는 **오프닝 홀드·엔딩 홀드**에서 실행한다. `focus-frame`(초점 프레임 안착 ±2px), `detail-hidden`·`chip-in-focus`, `title-lines`(2줄)·`title-count`(보이는 제목 1개), `map-current`(롱폼), `cut-off`(화면 가장자리에서 잘린 글자·아이콘), `safe-*`·`zoom-*`, `overview-bounds`·`detail-in-overview`·`edge-count`(덧선·화살표 제외 주선만), `forbidden-element`, `episode-number`가 모두 0이어야 한다.
- 검증기를 바꿨으면 초점 노드를 40px 밀었을 때 `focus-frame`이 잡히는지 자체 점검한다(샘플 `tools/verify.py`의 self 시점).
- 클릭 전후(클릭 −0.05초 / +0.45초)에 라벨 `color`만 바뀌고 라벨의 테두리·윤곽선 **두께와 스타일**, 노드 외곽선·면·그림자, 부모 배경이 그대로인지 계산된 스타일로 비교한다. 두께 0인 `border`·`outline`의 색은 `currentColor`라 글자색을 따라 바뀌므로 비교에서 제외한다.
- 커서는 `verify-video-cursor.js`로 클릭 시점과 이동 직전에 잰다. 렌더 MP4에서는 줌 중간 프레임을 뽑아 이웃 노드 칩·연결선이 보이는지, 월드 제목이 가장자리에서 잘려 지나가지 않는지 눈으로 확인한다.
- 얼굴·발표자 캠·프로필 사진·전사 자막이 한 프레임도 없는지 확인한다.

## 컬러 계획 질문

스타일을 고른 다음 **항상 별도 질문으로 확정**한다. 사용자가 앞에서 색을 언급했어도 그 값을 `사용자 지정안`으로 보여 주고 확인받는다. 질문 없이 기본 팔레트로 진행하지 않는다.

선택지에는 아래 세 가지를 제시한다.

1. `추천안` — 대본 주제와 선택한 스타일에 맞춰 새로 만든 60/30/10 조합. HEX와 색 이름을 모두 표시한다.
2. `스타일 시그니처` — 아래 기본 조합을 표시한다.
3. `사용자 지정안` — 사용자가 원하는 HEX 또는 색 이름을 직접 적는다.

| 스타일 | 60 배경 | 30 글자/표면 | 10 포인트 |
|---|---|---|---|
| 페이퍼 콜라주 | `#F2EFE4` 웜 아이보리 | `#24251F` 딥 잉크 | `#B75240` 브릭 레드 |
| 맥 파인더창 | `#111318` 그래파이트 | `#F4F6FA` 쿨 화이트 | `#4A8DFF` 셀렉션 블루 |
| 네오 브루탈리즘 | `#F6F0DC` 웜 크림 | `#111111` 잉크 블랙 | `#FF4D2E` 펀치 오렌지 |
| 다이내믹 타일 창 | `#0A0A0B` 잉크 블랙 | `#ECECEC` 소프트 화이트 | `#FF4A3D` 시그널 레드 |
| 노드 줌 프로세스 | `#0D1014` 잉크 블랙 | `#ECEFF3` 쿨 오프화이트 | `#2EE6A6` 시그널 민트 |

확정한 팔레트는 롱폼·숏폼·CTA에 동일하게 이어 간다. 스타일 시그니처는 추천 출발점이며, 사용자가 고른 다른 조합이 우선한다.
