# Paper Briefing — 영상 슬라이드 디자인 프리셋

프로파일 ID: `paper-briefing`

적용 대상: `/sins-video-consource` 옵션 2의 영상 슬라이드. 영상 제작 시 기본 디자인으로 사용하되, 사용자가 다른 스타일을 지정하면 그 요청을 따른다. 옵션 1의 대본 작성과 옵션 3의 웹 프레젠테이션에는 자동 적용하지 않는다.


## 기존 스킬 레이아웃 배제 (필수)

사용자가 유튜브 레퍼런스 스타일만 쓰라고 지정한 경우, 아래 **기존 `/sins-video-consource` 영상 레이아웃은 전부 사용하지 않는다.** 화면은 이 문서의 종이·잉크·밑줄 구성만 따른다.

쓰지 않는 것:
- `.lf-label` / `.lf-title` / `.lf-subtitle` / `.lf-body` 고정 슬롯과 전 씬 동일 y좌표
- 본문 `minFill` · `minFillX` 채움률 강제, wordfill 네온 키워드, 골드 글로우
- 그리드·대리석·에디토리얼 골드 기본 배경, 카드 3~4열 대시보드, 아이콘+게이지 필수
- `scripts/verify-frame.js` 롱폼 검사. 합격 기준은 `scripts/verify-paper-frame.js`와 실제 렌더 검수만 사용한다

레이아웃 어긋남 금지:
- 글자·밑줄·출처는 `.pb-content` 안전영역(`x192..1728, y208..854`) 안에만 둔다
- 종이 가장자리 찢김이 제목·문장과 겹치면 안 된다
- 챕터 번호 상자와 챕터명은 한 줄로 정렬하고, 종이 바깥 왼쪽 위(`x120, y66`)에만 둔다
- 비교 패널 두 장은 같은 높이·같은 안쪽 여백으로 맞춘다
- 한 장에 주장이 넘치면 장면을 나누고, 글자 크기를 줄여 밀어 넣지 않는다
- 하단 15%(`y918` 이후)에는 핵심 글자를 두지 않는다


## 문장 줄바꿈 (필수)

종이 위 글자는 한 덩어리로 가로로 밀지 않는다.

- 마침표(`.`)로 끝나는 문장은 그 지점에서 줄을 바꾼다. HTML에서는 문장마다 별도 줄(`<br>` 또는 블록)로 나눈다.
- 한 문장이 안전영역 가로의 약 70%(약 1080px, 본문 기준 대략 28~34자)를 넘으면 조사·접속 앞에서 자연스럽게 한 번 더 줄을 바꾼다.
- `word-break: keep-all`을 유지하고, 띄어쓰기가 화면에서 사라지지 않게 `white-space`를 접거나 자간을 과도하게 줄이지 않는다.
- 제목도 두 문장이면 마침표 뒤에서 나눈다. 본문이 세 줄을 넘으면 장면을 나눈다. 글자 크기를 줄여 한 줄에 밀어 넣지 않는다.

## 아이콘과 그래픽 (필수)

텍스트만 있는 장면은 불합격이다. 종이·잉크 톤 안에서 **매 장면마다** 주장과 맞는 그래픽을 넣는다.

- 장면마다 아이콘·픽토·간단한 도해 중 하나 이상을 둔다. 비교는 패널마다 아이콘, 과정은 단계 아이콘, 주장은 큰 픽토 하나와 밑줄 문장을 짝짓는다.
- 아이콘은 잉크색(`#292B26`) 또는 벽돌색(`#B75240`) 라인/단색 픽토그램이다. 네온, 이모지 원본, 입체 3D, 골드 글로우는 쓰지 않는다.
- 아이콘은 Koboyo 또는 같은 굵기의 라인 아이콘을 쓰고, 브랜드가 나오면 공식 로고를 쓴다.
- 가짜 게이지·미니바·근거 없는 막대는 계속 금지한다. 도해는 관계·순서·대비를 보여 주는 선과 도형만 허용한다.
- 그래픽이 글자를 가리거나 찢긴 종이 가장자리와 겹치면 안 된다. 아이콘은 안전영역 안에 두고, 제목보다 시선을 먼저 가져가도 된다.

## 말 싱크 밑줄과 장면 애니메이션 (필수)

- 내레이션이 그 어구를 말하는 순간에 벽돌색 밑줄이 왼쪽에서 오른쪽으로 그려진다(`scaleX` 0→1, 0.35~0.55초). 말이 끝나기 전에 미리 그리지 않는다.
- 이미 그린 밑줄은 그 장면이 끝나는 동안 유지하고, 같은 어구에 다시 그리지 않는다.
- 장면마다 등장 연출을 다르게 쓴다. 허용 예: 종이 페이드+밑줄 드로잉, 아이콘 팝 후 문장 순차, 비교 패널 슬라이드+연결선, 과정 단계 순차 드로잉, 인용 왼쪽 막대 성장.
- 한 편에서 등장 연출은 **4종 이상** 나오게 한다. 전 장면을 같은 페이드만으로 반복하지 않는다.
- 무한 회전, 둥둥 아이들, 글로우 펄스, 배경 파티클, 네온 타이포는 계속 금지한다. 등장 후 읽는 동안 멈춰도 된다.

## 레퍼런스와 해석 범위

레퍼런스는 [사용자가 제공한 YouTube 영상](https://www.youtube.com/watch?v=ugMdIxo08qk&t=474s)이다. 직접 확인한 화면은 약 **7:59–8:06** 구간이다. 아래 규칙은 그 구간에서 확인한 배치·재질·강조 방식을 재사용할 수 있도록 정리한 것이다. 영상 전체에 같은 연출이 사용된다고 단정하지 않는다.

확인한 특징:

- 무광에 가까운 검은 배경 위에 큰 아이보리색 종이 한 장이 놓인다.
- 종이 가장자리는 조금씩 찢긴 듯 불규칙하다.
- 검은 글자에 차분한 벽돌색 손그림 밑줄과 짧은 강조 막대를 더한다.
- 검은 배경의 왼쪽 위에는 작은 흰색 둥근 사각형 챕터 번호와 작은 챕터명이 있다.
- 원문과 번역을 설명하는 장면은 큰 종이 안에 작은 종이 두 장을 나란히 놓는다.
- 종이 아래쪽에는 읽는 데 필요한 여백이 남는다. 발표자는 종이 바깥 오른쪽 아래에 작게 배치된다.

원본 영상에는 종이 윗부분에 마스킹테이프가 있지만, 사용자의 요청에 따라 적용 디자인에서는 테이프 장식을 사용하지 않는다.

**아래 HEX 값은 화면에서 픽셀을 추출한 값이 아니라 관찰한 인상을 바탕으로 정한 근삿값이다.** 원본의 종이 이미지·텍스트·발표자 화면을 복제하지 않고 재질과 구성 방식을 참고한다.

## 롱폼 좌표와 폰트

설계 좌표는 **1920×1080**, 출력은 기존 규격인 **2560×1440**을 유지한다. 배율은 `4/3`이다. 해상도·프레임레이트·롱폼 무자막·소스 품질 규칙은 이 프리셋으로 변경하지 않는다.

| 요소 | 기본 좌표 | 규칙 |
|---|---|---|
| 챕터 그룹 | `x120, y66` | 작은 번호 상자와 챕터명. 페이지수는 강제하지 않는다 |
| 큰 종이 | `x120, y150, w1680, h770` | 기본 외곽. 약한 찢김 윤곽으로 가장자리만 변형 |
| 종이 내부 텍스트 안전영역 | `x192..1728, y208..854` | 제목·본문·도해·출처 모두 이 안에서 설계 |
| 보조 풋노트 | 종이 내부 하단, `y854` 위 | 필요할 때만 한 줄. 공간이 부족하면 다음 장으로 이동 |

찢김 윤곽과 종이 무늬는 한 영상 안에서 고정해 씬 전환 때 재질이 튀지 않게 한다.

하단 **약 15%(`y918` 이후)**에는 핵심 글자·수치·출처를 두지 않는다. 종이 외곽이나 배경 장식은 걸칠 수 있다. 발표자 영상은 실제 소스가 있을 때만 오른쪽 아래 종이 바깥에 작게 배치한다. 발표자가 없으면 빈 캠 자리를 따로 예약하거나 가짜 인물을 만들지 않는다.

제목 폰트는 현재 스킬의 `KookminUniversityHaeongSans` 400, 본문은 `Presentation` / Freesentation 300을 유지한다. 제목 계열에 `bold`, `700`, `<b>`, `<strong>` 또는 브라우저 합성 볼드를 사용하지 않는다. 강조는 크기·잉크색·밑줄·여백으로 만든다. 본문도 굵은 폰트 파일이 실제로 등록된 경우에만 해당 굵기를 사용한다.

권장 출발 크기는 제목 68~86px(선언형 104px), 본문 32~42px, 보조 26~30px, 출처 22~24px다. 문장이 넘치면 정보량이나 장면을 나누며 글자를 작게 줄여 밀어 넣지 않는다. 장면의 성격에 따라 종이 내부 제목·본문 위치를 바꿀 수 있다.

## 장면 구성 5종

한 장면에는 주장 하나를 둔다. 설명을 읽을 여백은 남기되, 텍스트만으로 채우지 않고 아이콘·도해를 함께 둔다.

| 구성 | 쓰는 상황 | 화면 구성 |
|---|---|---|
| `statement` | 핵심 주장·질문·결론 | 큰 픽토 하나 + 마침표 기준 줄바꿈 문구, 말하는 순간 붉은 밑줄 |
| `compare` | 원문/번역·전/후·두 선택지 | 패널 두 장 + 각 패널 아이콘, 같은 기준의 짧은 제목, 비교 지점을 말하는 순간 밑줄로 연결 |
| `process` | 순서·원리·전개 | 2~4단계 아이콘과 연결선, 번호·짧은 라벨. 단계는 발화 순서대로 등장 |
| `data` | 검증 가능한 수치·추이 | 큰 수치 또는 간결한 차트 하나, 단위·기준·출처를 함께 표시. 붉은색은 주목할 데이터에만 사용 |
| `evidence` | 문서·인용·화면 증거 | 읽을 수 있는 원문 발췌나 허가된 화면, 핵심 밑줄, 별도 해석 영역. 출처와 인용 범위를 분명히 구분 |

비교 패널은 얇은 경계선이 꼭 필요할 때만 종이색 차이나 아주 약한 그림자로 구분한다. 대시보드형 카드 나열과 가짜 게이지는 쓰지 않는다. 아이콘과 도해는 매 장면에 넣되, 그 장면의 주장과 직접 연결되게 고른다.

**차트·미니바·비율·게이지는 확인된 실제 데이터가 있을 때만 만든다.** 수치가 없으면 단계·관계·개념 도해로 표현한다. 보기 좋게 채우기 위한 가짜 수치, 임의의 상대 비중, 근거 없는 길이 차이를 만들지 않는다. 시연용 가상 데이터가 꼭 필요하면 사용자에게 그 목적이 명확한 경우에만 사용하고 화면에 가상 예시임을 표시한다.

## 모션과 읽기 리듬

- 장면 진입은 짧고 부드러운 페이드 또는 작은 이동으로 처리한다. 종이가 크게 튀거나 계속 흔들리지 않는다.
- 내레이션이 해당 어구를 설명하는 순간 붉은 밑줄을 그린다. 이미 읽은 내용에 밑줄을 반복해서 그리지 않는다.
- 비교·과정 장면은 발화 순서에 따라 요소를 차례로 보여준다. 연결선·실제 데이터 막대는 설명 시점에 맞춰 한 번 그린다.
- 정보가 다 나타난 뒤에는 **읽을 시간 동안 정지**해도 된다. 3초마다 억지로 움직이지 않는다.
- 무한 아이콘 회전, 둥둥 뜨는 아이들 모션, 글로우 펄스, 배경 파티클, 네온 타이포는 사용하지 않는다.
- 전환 횟수나 모션 종류를 채우는 것보다 말과 화면의 일치를 우선한다. 참고 구간의 구체적인 애니메이션 시간을 측정한 것은 아니므로 고정된 원본 타이밍이라고 설명하지 않는다.

## 기존 규칙보다 우선하는 범위

아래 우선순위는 **`paper-briefing`이 활성화된 옵션 2에만** 적용한다. 다른 프로파일과 옵션 3의 기존 동작을 전역으로 바꾸지 않는다.

| 기존 규칙 | 이 프로파일에서 적용할 규칙 |
|---|---|
| 에디토리얼 골드·그리드가 영상 기본값 | 무광 검정 + 아이보리 종이 + 벽돌색 강조 |
| `.lf-label/.lf-title/.lf-subtitle/.lf-body`의 고정 세로 슬롯 | 이 문서의 종이 외곽·내부 안전영역 + 구성 5종에 맞춘 자유 배치 |
| 본문 `minFill: .5`, `minFillX: .7` | 최소 채움률 강제 없음. 읽기 여백 허용, 실제 넘침·안전영역 위반은 계속 검사 |
| 핵심 주장은 네온 `wordfill` | 종이 위 큰 잉크색 문구와 붉은 손그림 밑줄 |
| 모든 본문 씬에 아이콘+차트/게이지 필수 | 매 장면 라인 아이콘·도해 필수. 가짜 게이지·미니바는 금지 |
| 모든 나열 항목의 미니바 필수 | 실제 수치가 있을 때만 시각화. 장식용 막대 생략 |
| 등장·회전 아이들 기본값, 3초 이상 정지 금지 | 절제된 등장·밑줄·순차 표시 후 읽기 정지 허용 |
| 골드 활성 글로우·네온 펄스 | 벽돌색 잉크·밑줄·작은 강조 막대 |
| 한 편의 모션 종류를 네온/아이들으로 채움 | 말 싱크 밑줄 + 장면마다 다른 등장 연출 4종 이상. 무한 아이들·네온 금지 |

기존 `scripts/verify-frame.js`의 `longform` 검사는 옛 슬롯과 채움률을 기준으로 하므로 이 프로파일에서는 사용하지 않는다. 대신 함께 제공하는 `scripts/verify-paper-frame.js`를 페이지에 로드하고, 폰트 로딩과 등장 모션이 끝난 뒤 `__verifyPaperFrame()`을 실행한다. 활성 씬에는 `.scene.is-active`, 스테이지에는 `.stage` 또는 `.lf-stage`를 사용하고 필수 요소에는 `.pb-chapter`, `.paper-wrap`, `.pb-content`, `.pb-title` 클래스를 붙인다. 검증기는 설계 화면비·종이 슬롯·내용 안전영역·넘침·제목 굵기·실제 폰트 로딩을 검사한다. 텍스트끼리의 겹침·밑줄·발표자 충돌과 읽기 리듬은 실제 화면으로 별도 검수한다. 기존 `longform`과 숏폼 검증은 변경하지 않는다.

## 숏폼 적용

숏폼에는 같은 종이·잉크·밑줄의 시각 언어만 옮긴다. 롱폼 좌표를 그대로 축소하지 않는다.

기존 숏폼의 1080×1920 규격, 플랫폼 안전영역, 우측 UI 데드존, 키커·제목·본문·자막 슬롯, 고정 자막 위치, 길이 제한, 마지막 CTA 문구·타이밍은 유지한다. 작은 화면에서 텍스트를 읽을 수 있도록 종이 안의 항목 수를 줄이고 한 장면을 필요하면 나눈다. CTA는 기존 전용 규칙을 그대로 적용한다.

## 스킬 연결과 요청 분기

스킬은 STEP 0 앞의 요청 유형 판별과 옵션 2 진입부에서 이 문서를 읽는다. 이 문서는 옵션 2의 디자인 규칙에 우선하며 옵션 1·3에 자동 적용하지 않는다.

1. 스타일 변경·레퍼런스 분석·디자인 샘플만 요청하면 스타일 문서와 대표 장면 미리보기를 만든다. 실제 영상에 필요한 대본·오디오·숏폼 선택은 이 단계에서 묻지 않는다.
2. 실제 영상 제작은 기존 입력 확인·모드 판별·제작 범위·렌더·싱크·검증 절차를 유지한다. 이미 확정한 항목은 재질문하지 않는다.
3. 별도 스타일 지정이 없으면 영상은 `paper-briefing`을 사용한다. 사용자가 이 레퍼런스를 지정했다면 배경·색은 확정된 것으로 처리한다. 사용자가 다른 스타일을 지정하면 그 요청이 우선이다.
4. 롱폼 레이아웃·씬 설계·STEP 6-V·검수의 반복된 골드·고정 슬롯·아이콘·네온·아이들 규칙보다 이 프로파일을 우선한다.
5. 미리보기는 디자인 예시다. 실제 대본·내레이션이 없는 예시를 완성 영상이라고 표현하지 않는다.

## 미리보기와 제작 결과 검수

- 종이 내부 글자·밑줄·출처가 안전영역을 벗어나지 않는지 실제 렌더에서 확인한다.
- 테이프 장식이 없고, 찢김 윤곽이 제목·문장과 겹치지 않는지 확인한다.
- 검은 바탕·아이보리 종이·벽돌색 강조의 역할이 일관적인지 확인한다.
- 발표자가 없는 결과에 불필요한 캠 빈자리가 없는지 확인한다.
- 비교는 같은 기준을 쓰고, 데이터는 단위·근거·출처를 갖추었는지 확인한다.
- 내레이션이 있는 실제 영상은 밑줄이 그 어구를 말하는 순간에 그려지는지, 장면마다 등장 연출이 다른지 재생해서 확인한다.
- 마침표 뒤에서 줄이 바뀌고, 긴 문장이 한 줄로 밀리지 않는지 확인한다.
- 텍스트만 있는 장면이 없는지, 아이콘·도해가 안전영역 안에 있는지 확인한다.
